**Approach / رویکرد:** Binary Search / جستجوی دودویی

## Idea / ایده

چون آرایه به صورت صعودی مرتب شده است، به جای اینکه از ابتدا تا انتها جستجو کنیم، هر بار عنصر وسط محدوده را بررسی می‌کنیم.

- اگر `target === nums[mid]` باشد، `mid` را برمی‌گردانیم.
- اگر `target < nums[mid]` باشد، سمت راست را حذف می‌کنیم.
- اگر `target > nums[mid]` باشد، سمت چپ را حذف می‌کنیم.
- این کار را تا زمانی ادامه می‌دهیم که `left <= right` باشد.
- اگر `target` پیدا نشود، `-1` برمی‌گردانیم.

در هر مرحله تقریباً نصف محدوده حذف می‌شود.

## Complexity / پیچیدگی

- **Time / زمان:** `O(log n)` — چون در هر مرحله نصف محدوده‌ی جستجو حذف می‌شود.
- **Space / حافظه:** `O(1)` — چون فقط چند متغیر مثل `left`، `right` و `mid` استفاده می‌کنیم و آرایه‌ی جدیدی نمی‌سازیم.

## Notes (optional) / یادداشت (اختیاری)

`mid` از `left` و `right` محاسبه می‌شود و چون `left` و `right` در هر مرحله تغییر می‌کنند، `mid` هم باید در هر iteration دوباره محاسبه شود.

همچنین فهمیدم که وقتی `target > nums[mid]` است، می‌توانیم تمام سمت چپ را کنار بگذاریم و `left = mid + 1` کنیم؛ و وقتی `target < nums[mid]` است، `right = mid - 1` می‌شود.
